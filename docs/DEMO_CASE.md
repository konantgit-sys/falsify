# Демо-кейс: запись без подписанного времени проходит как `verified_pass`

Это не описание товара, а сам товар: один настоящий дефект, упакованный по пяти
критериям, которые покупатель может перезапустить.

## Дефект

`falsify.record.verify()` проверяет самосогласованность записи — версию, числа,
хеш, подпись, совпадение ключа, связь с предыдущей записью, — но **не проверяет
полноту обязательных полей**. Запись, у которой нет `timestamp` (единственного
времени, лежащего под подписью; `ts_human` по формату `canon_v1.3` вне подписи),
при пересчитанном `record_sha256` и заново поставленной подписи получает вердикт
`verified_pass`.

Следствие: инструмент говорит «проверено» о записи, которая не утверждает,
когда она сделана. Это ровно тот класс отказа, который falsify обещает ловить.

## Наблюдаемое поведение (числа до фикса)

`python3 tests/demo_required_fields.py` на коде до фикса:

```
verdict          : verified_pass        ← дефект
checks           : version pass, numbers pass, hash pass, signature pass
отсутствует      : timestamp, payload
код возврата     : 1                    ← утверждение теста ложно
```

Тест утверждает: запись без `timestamp` и `payload` обязана получить
`verified_fail` и назвать отсутствующие поля. До фикса утверждение ложно, и это
и есть воспроизведение.

## Критерии приёмки — все пять, по порядку

1. **Воспроизведение до фикса.** На коммите `eba3860` (или любом предке фикса)
   `tests/demo_required_fields.py` печатает `verdict: verified_pass` и выходит с
   кодом 1. Тест печатает дайджест окружения: версию интерпретатора, хеш
   зависимостей, идентификатор образа ОС.
2. **Прохождение после фикса.** С фиксом тот же тест выходит с кодом 0 и
   печатает `verdict: verified_fail`, в причинах — `timestamp`, `payload`.
   Полный набор `tests/run_tests.py` остаётся **36/36** — ни одна проверка не
   снята и не пропущена.
3. **Откат возвращает падение.** После откатa фикса (`git revert`) тест снова
   выходит с кодом 1 и печатает **тот же** текст утверждения, а не другое.
4. **Несвязанные фикстуры байт-в-байт.** Вывод `tests/run_tests.py` до фикса и
   после откатa совпадает по SHA-256 (см. `evidence/`, поле `unrelated_sha256`).
   «Всё ещё проходит» не принимается: сжавшийся набор проходит и это.
5. **Доказательства подписаны.** `tests/evidence.py` собирает три прогона
   (до фикса, после фикса, после откатa), каждый — с SHA-256 по сырым байтам и
   временем UTC; бандл подписывается Ed25519, публичный ключ лежит рядом.
   Независимый тестер перезапускает все пять по бандлу, не доверяя архиву.

## Границы кейса — что он НЕ делает

- не проверяет `payload` по схеме: кейс только про наличие обязательных полей;
- не вводит доверенную третью сторону: подпись доказывает целостность бандла,
  но не честность автора;
- не трогает `ts_human`: по формату это поле вне подписи, и кейс это не
  «исправляет».

## Что покупатель объявляет до старта

`repo_url`, `commit_sha`, команду прогона, список «несвязанных фикстур» и правило
приёмки. Правило фиксируется до работы и хешируется — иначе приёмка недоказуема.

## Цена

Пакет (спека + падающий тест + фикс + откат) — 6 USDC / 10000 sats,
deliver-first, оплата после приёмки.
